# 本地联调与测试手册（frontend/web + frontend/admin）

本手册说明如何在本机拉起整套服务、用哪些账号登录，以及用户端和运营后台的测试清单。所有数据都在独立的开发库 `uft_dev` 里；自动化测试使用另一个库 `uft`，两者互不影响，跑测试不会弄脏你的数据。

---

## 1. 组件与端口

| 组件 | 地址 | 作用 |
|---|---|---|
| frontend/web（用户端） | http://localhost:3000 | 模型广场、Playground、个人中心；`/v1`、`/console` 由 Vite 转发到 gateway |
| frontend/admin（运营后台） | http://localhost:3001 | 运营后台；`/admin-api` 由 Vite 转发到 cmd/admin |
| cmd/gateway | http://localhost:8080 | 对外 API：`/v1/*`（API Key 鉴权）、`/console/*`（用户登录态） |
| cmd/admin | http://localhost:8081 | 运营后台 API |
| cmd/worker | — | 后台任务：请求日志分区、小时汇总、健康事件落库、对账、风控 |
| mockupstream | http://127.0.0.1:18099/v1 | 本地模拟的 OpenAI 兼容上游，不需要真实厂商账号 |
| Postgres | localhost:55432 | 由 `tools/devdb` 启动的嵌入式 PostgreSQL；开发库 `uft_dev`，测试库 `uft` |
| Redis | localhost:6379 | Windows 上用 Memurai |

## 2. 启动

在仓库根目录用 Git Bash 执行。前提：Redis 在 6379 运行（Windows 上是 Memurai 服务，`netstat -an | grep 6379` 能看到 LISTENING）。

```bash
./scripts/dev-all.sh start     # 一键启动：数据库 + 后端 + 两个前端
./scripts/dev-all.sh status    # 查看各组件状态
./scripts/dev-all.sh stop      # 全部停止（包括数据库）
./scripts/dev-all.sh restart   # 重启（会重新编译后端，改了 Go 代码后用它）
./scripts/dev-all.sh reset     # 清空开发库并重新写入演示数据
```

`start` 依次做这些事，已经在运行的组件会跳过，重复执行没有副作用：

1. 数据库：没在运行就启动 `tools/devdb`（:55432，数据目录 `tmp/testpg`；首次会下载 PostgreSQL 二进制，要一两分钟）
2. 后端：开发库 `uft_dev` 不存在就创建，迁移到最新版本，编译并启动 mock 上游(:18099)、admin(:8081)、gateway(:8080)、worker
3. 演示数据：空库时写入账号、供应商、模型、测试用户；已经写过就跳过
4. 前端：没有 `node_modules` 就先 `npm install`，然后启动 frontend/web(:3000) 与 frontend/admin(:3001)

只想单独操作后端时可以用 `./scripts/dev-stack.sh up|down|status|reset|seed`（需要数据库已在运行）。

- **日志**：在 `tmp/dev-stack/*.log`（前端日志是 `web.log`、`admin-ui.log`）。
- **种子输出**：seed 打印的账号与 API Key 同时保存在 `tmp/dev-stack/seed-output.txt`。

> 启动脚本打开了 `UFT_ADMIN_ALLOW_PRIVATE_UPSTREAM=true`，允许 http 和内网上游，这样才能接本机的 mock 上游。**这是开发专用设置，生产环境不能开。**

## 4. 演示数据

- **汇率**：USD→CNY 7.2。
- **供应商**：`mockai`，上游账号 `mock-account` 指向 mock 上游，挂 1 把密钥。
- **模型**：以下 7 个模型通过批量导入上架，售价 = 成本 × 汇率 × 1.3（加价 30%），由服务端用十进制计算。

| 模型 | 类型 | 成本（USD/百万 token，输入 / 输出） | 售价（CNY/百万 token，输入 / 输出） | 用途 |
|---|---|---|---|---|
| mock-chat | chat | 0.5 / 1.5 | 4.68 / 14.04 | 常规对话，回显输入；已配置展示元数据 |
| mock-chat-pro | chat | 2 / 6 | 18.72 / 56.16 | 贵一些的模型 |
| mock-reasoner | chat | 1 / 4 | 9.36 / 37.44 | — |
| mock-embedding | embedding | 0.1 / 0.1 | 0.936 / 0.936 | 向量接口 |
| mock-fail | chat | 0.5 / 1.5 | 4.68 / 14.04 | **上游总是返回 500**：测失败日志、熔断、渠道健康 |
| mock-limit | chat | 0.5 / 1.5 | 4.68 / 14.04 | **上游总是返回 429**：测密钥冷却 |
| mock-slow | chat | 0.5 / 1.5 | 4.68 / 14.04 | **上游延迟 3 秒**：测延迟统计与 P95 |

## 5. 测试清单

### 5.1 用户端（frontend/web）

| # | 场景 | 步骤 | 预期 |
|---|---|---|---|
| W1 | 模型广场 | 打开 http://localhost:3000 | 列表里有 7 个 mock 模型，mock-chat 显示展示名 "Mock Chat" 和描述 |
| W2 | 注册 | 右上角注册一个新邮箱（密码至少 8 位） | 注册成功并自动登录；运营后台「账户」里出现新账户，余额 0 |
| W3 | 登录 | 用 demo@uft.local 登录 | 进入个人中心 |
| W4 | API Key | 个人中心 → API 密钥 → 新建 | 明文只显示一次；后台「API 密钥」页能按前缀搜到它 |
| W5 | Playground | 连接 API Key → 选 mock-chat → 发消息 | 收到"这是来自 mockupstream 的回复……"；流式、非流式都正常 |
| W6 | 余额与用量 | 调用几次后查看个人中心的用量 / 余额 | 余额减少；先扣赠送余额，再扣现金 |

也可以直接用 curl 调 API（`$KEY` 换成你的 API Key）：

```bash
curl http://localhost:8080/v1/chat/completions -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"mock-chat","messages":[{"role":"user","content":"hello"}]}'
curl -N http://localhost:8080/v1/chat/completions -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"mock-chat","stream":true,"messages":[{"role":"user","content":"hello"}]}'
curl http://localhost:8080/v1/embeddings -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"mock-embedding","input":"hello"}'
curl http://localhost:8080/v1/usage -H "Authorization: Bearer $KEY"
```

## 6. 清空重来

```bash
./scripts/dev-all.sh reset   # 停后端 → 删除并重建 uft_dev → 迁移 → 启动后端 → 写入演示数据
```

用户端的登录态和 API Key 保存在浏览器里。清空数据后，要么退出登录并清掉 localStorage 里的旧 Key，要么换一个无痕窗口。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 单独用 `dev-stack.sh up` 提示 Postgres 没在运行 | 用 `./scripts/dev-all.sh start`，它会先把数据库拉起来 |
| 提示端口已被占用 / 某个组件起不来 | 先 `./scripts/dev-all.sh stop` 再 `start`（stop 按端口结束进程）；仍失败就看 `tmp/dev-stack/<组件>.log` |
| 提示 Redis 没在运行 | 启动 Memurai 服务（管理员终端执行 `net start Memurai`），脚本不负责启动它 |
| 新上架或改价后，网关还是旧价格 | 网关每 10 秒刷新一次目录快照，稍等片刻 |
| 工作台数字没变化 | 统计结果缓存 60 秒；30 天视图读小时汇总表，worker 每 5 分钟更新一次 |
| 渠道健康显示"未连接 Redis" | cmd/admin 启动时连不上 Redis，确认 Memurai 在运行后重启后端 |
| 用户端调用返回 401 | API Key 错误或已吊销；或 reset 之后浏览器里还存着旧 Key |
| 调用返回 402 / 余额不足 | 在运营后台给该账户人工调账 |
| seed 提示"已经 seed 过" | seed 只对刚 reset 的空库运行，按第 6 节清空重来 |
| 用 `go test` 跑自动化测试 | 测试默认连 `localhost:5432/uft`；用本手册的库时设置 `UFT_TEST_PG_DSN=postgres://uft:uft@localhost:55432/uft?sslmode=disable`。测试数据写进 `uft` 库，不影响 `uft_dev` |
