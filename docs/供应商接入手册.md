# 供应商接入手册

> 面向运营 / 后端：如何把一个新的上游模型供应商接入网关，让用户通过统一的 `/v1/*` 接口（见 frontend/web 开发者文档）调用它的模型。
> 设计背景见仓库根目录《多供应商统一接口适配技术设计方案》《多供应商接口统一技术实施方案》。

## 1. 原理一句话

网关对外只有一套 OpenAI 形状的接口。每个上游账号（`provider_accounts`）可以挂一份**供应商方言**（`extra.dialect`），描述这家供应商与 OpenAI 形状的差异：
路径、默认参数、参数改名、音色映射、错误表达、用量字段、不支持的端点……网关按方言改写请求和响应；
差异大到无法用配置表达的（如百炼原生图像 / 语音接口），由一个具名 **codec**（Go 代码，`internal/adapter/codec_*.go`）处理，方言里只引用名字。

```
用户 ──OpenAI 形状──▶ 网关 relay ──▶ 方言（预设 ← 账号覆盖，深合并）──▶ codec ──▶ 上游
```

## 2. 接入流程

| 步骤 | 做什么 | 工具 |
|---|---|---|
| 1 | 查有没有同名内置预设 | `internal/dialect/presets/<code>.json`，或后台「上游账号 → 供应商方言 → 从预设开始」 |
| 2 | 用 providercheck 实测各项能力 | `go run ./cmd/providercheck ...`（见 §3） |
| 3 | 不通过的能力：调方言 → 重测；配置表达不了 → 写 codec | §4、§5 |
| 4 | 后台接入：供应商 → 上游账号 → 密钥 | 后台「接入向导」，有同名预设时自动绑定 |
| 5 | 导入模型、定价、上架 | 「导入模型」；方言声明不支持的端点，对应类型的模型会被拒绝导入 |
| 6 | 端到端回归 | `tests/gateway_py`：`UFT_PROVIDER=<code> python onboard.py && pytest` |
| 7 | 提交认证报告，刷新能力矩阵 | `docs/provider-certifications/<code>.json`、`docs/provider-capability-matrix.md` |

方言保存后网关在下一次目录快照刷新（约 10 秒）后生效，无需重启。方言 JSON 不合法时保存被拒（400）；
若数据库里已有的方言无法解析，该账号状态视为 `dialect_error`，路由不再选它（不会带着错误的配置去打上游）。

## 3. providercheck：能力实测

```bash
# 单家实测，写报告
go run ./cmd/providercheck -provider dashscope \
  -base-url https://dashscope.aliyuncs.com/compatible-mode/v1 -key-env DASHSCOPE_API_KEY \
  -preset dashscope \
  -models "chat=qwen-flash,vlm=qwen3-vl-flash,embedding=text-embedding-v4,rerank=qwen3-rerank,image=qwen-image-3.0,tts=qwen3-tts-flash,asr=qwen3-asr-flash" \
  -out docs/provider-certifications/dashscope.json

# 临时覆盖方言（与预设深合并），用于调试
go run ./cmd/providercheck ... -preset openrouter -dialect '{"endpoints":{"images":{"path":"/images"}}}'

# 汇总全部报告为能力矩阵
go run ./cmd/providercheck -matrix docs/provider-certifications -matrix-out docs/provider-capability-matrix.md
```

- 检查项：Key 校验、模型列表，以及 chat / chat_stream / tools / vlm / embedding / rerank / image / tts / asr 九项能力。
  走的是网关同一套 adapter 与 codec，所以 providercheck 通过 ≈ 网关可用。
- 没给模型的能力记为「未测」；方言声明 `supported:false` 的记为 ⛔。
- asr 复用 tts 生成的音频，所以测 asr 时请同时给 tts 模型。
- Key 只从环境变量读（`-key-env`），不要把 Key 写进命令行历史。

## 4. 方言字段参考

方言 JSON 写在账号的 `extra.dialect`。`preset` 引用内置预设，其余字段与预设深合并（对象逐键合并，数组 / 标量整体替换）。

### 4.1 `endpoints.<端点>`

端点名：`chat`、`embeddings`、`rerank`、`images`、`speech`、`transcriptions`。

| 字段 | 作用 | 例 |
|---|---|---|
| `supported` | `false` = 该供应商不提供此端点：路由排除、导入 / 建渠道被拒 | 方舟 `rerank` |
| `codec` | 用具名 codec 处理（见 §5） | `"dashscope.image"` |
| `by_model` | 按上游模型名正则覆盖 `codec` / `supported` | `[{"match":"^wan","codec":"..."}]` |
| `url` | 绝对地址模板，`{origin}` = base_url 的 `scheme://host`；优先于 `path` | 百炼 rerank `{origin}/compatible-api/v1/reranks` |
| `path` | 相对 base_url 的路径覆盖 | OpenRouter 图像 `/images` |
| `defaults` | 客户端没传才补 | `{"response_format":"mp3"}` |
| `force` | 总是覆盖 | `{"watermark":false}` |
| `drop` / `rename` | 删字段 / 改名 | `{"max_tokens":"max_completion_tokens"}` |
| `voice_map` / `size_map` | OpenAI 音色 / 尺寸 → 上游取值 | `{"alloy":"Cherry"}` |
| `transforms` | 具名变换（见下） | `["ark_n_to_sequential"]` |
| `usage` | 计量项 → 响应 JSON 路径候选，取第一个非零值 | `{"input_tokens":["usage.total_tokens","usage.search_units"]}` |
| `limits` | 对用户可见的约束，汇总到 `GET /v1/catalog` 的 `limits` | `{"b64_only":true}`、`{"audio_formats":["wav"]}`、`{"max_file_bytes":7340032}`、`{"response_formats":["json"]}` |

请求改写顺序：`defaults → rename → drop → force → voice_map/size_map → transforms`，之后才应用渠道的 `param_overrides`（渠道级优先）。

具名变换（`internal/adapter/dialect_apply.go`）：

| 名称 | 作用 |
|---|---|
| `voice_prefix_upstream_model` | 短音色名补上游模型前缀（SiliconFlow：`alex` → `FunAudioLLM/CosyVoice2-0.5B:alex`） |
| `ark_n_to_sequential` | 方舟图像：`n>1` 转成组图参数 |
| `embedding_base64_encode` | 上游只支持 float 时，客户端要 base64 由网关编码 |

### 4.2 其它段

| 字段 | 作用 | 状态 |
|---|---|---|
| `errors.body_error_field` | HTTP 200 但响应体 / SSE chunk 带此顶层字段 = 失败（OpenRouter `error`）；非流式会换渠道重试，流式中途则给客户端发错误 chunk | 生效 |
| `errors.in_band_patterns` | 200 响应文本含这些子串 = 配额 / 余额耗尽 | 生效 |
| `chat.thinking_default` / `force_single_tool_call` / `strict_messages` / `single_system_message` / `min_max_tokens` | 对话请求的行为差异 | 生效 |
| `transport.extra_headers` / `keyless` | 附加请求头 / 不发 Authorization | 生效（含模型发现） |
| `auth.validation` | Key 校验方式：`models`（默认）/ `url` / `chat_probe` | providercheck 全部生效；后台模型发现只支持 `url` |
| `catalog.list_paths` | 列模型的路径（多个合并去重） | providercheck 与后台模型发现生效 |
| `transport.timeout_ms` | 非流式请求的整体超时（含读响应体），超时换渠道；流式请求不受限 | 生效 |
| `auth.alternate_hosts` | 主域名对 Key 返回 401/403 时依次改用的备用 base_url（智谱国内站 / 国际站），按 Key 记住可用域名，不冻结 Key | 生效 |
| `errors.challenge_is_transient` | 带 `cf-mitigated: challenge` 的 403 按上游不可用处理（换渠道），不当作 Key 失效 | 生效 |
| `region`、`notes` | 说明性字段 | 不影响行为 |

## 5. 什么时候写 codec

方言能表达的：路径、参数、默认值、映射、用量路径、错误字段。表达不了的才写 codec，典型情形：

- 请求 / 响应结构完全不同（百炼图像 `output.choices[].message.content[].image` → `data[].url`）；
- 需要额外的网络动作（百炼 TTS 返回音频 URL，网关下载后回给用户——下载只允许 `*.aliyuncs.com`，防 SSRF）；
- 换协议（百炼 ASR 是 chat + `input_audio`，网关把 multipart 转成 data URL）。

步骤：在 `internal/adapter/codec_<vendor>.go` 实现 `Codec`（`Build` + `Decode`），注册到 registry，把名字加进 `dialect.KnownCodecs`，
在 `dialect_codec_test.go` 用 httptest 假上游写单测。codec 返回 `InBandError` 表示「上游 200 但其实失败」，relay 会按错误分类重试或回给用户。

## 6. 已知的坑（实测）

| 供应商 | 现象 | 处理 |
|---|---|---|
| OpenRouter | `GET /models` 不鉴权，无效 Key 也能列出模型 | `auth.validation` 用 `{origin}/api/v1/key` |
| OpenRouter | `/models` 默认只列对话模型 | `catalog.list_paths` 加 `?output_modalities=all` 与 `/embeddings/models` |
| OpenRouter | HTTP 200 里带 `error`；流式中途报错 | `errors.body_error_field: "error"` |
| OpenRouter | TTS 不传 `response_format` 返回 PCM | `speech.defaults.response_format: "mp3"` |
| OpenRouter | Google / OpenAI 模型有地区限制 | 网关把地区类错误归为上游不可用并换渠道；所有渠道都不行返回 `503 no_available_channel` |
| OpenRouter | rerank 偶发 503 overloaded | 瞬时故障，重试即可 |
| 百炼 / OpenRouter | qwen-image 同步生成要 45–60 秒，偶尔超过 60 秒 | 网关等响应头的超时按端点区分：对话等 60 秒、图像 180 秒（`relay.Config.UpstreamHeaderTimeout` / `ImagesHeaderTimeout`）；此前统一 60 秒会把慢的图像请求误判为连接失败 |
| 百炼 | compatible-mode 的图像 / TTS / rerank 不可用或不是 OpenAI 形状 | `dashscope` 预设的 codec 与 `url` 覆盖 |
| 百炼 | 向量不支持 `encoding_format=base64` | `embedding_base64_encode` |
| 百炼 | ASR 文件上限约 7 MB，只支持 json | `limits.max_file_bytes` / `response_formats` |
| 方舟 | 图像不认 `n`、尺寸至少 2K、默认带水印；无通用 rerank；语音是独立的豆包语音协议 | `volcengine` 预设（未实测认证） |
| 推理模型 | `max_tokens` 太小时 `content` 为空（全用在思考上） | 用户文档已提示 ≥1024；方言可设 `chat.min_max_tokens` |
| Voxtral 等 ASR | 不带语言参数时会「翻译」而不是转写 | 测试档案带 `language`；用户侧建议显式传 |

## 7. 预设清单与认证状态

| 预设 | 状态 |
|---|---|
| `siliconflow`、`openrouter`、`dashscope` | 2026-10-02 实测认证，9 项全部通过（见能力矩阵） |
| `volcengine`、`deepseek`、`moonshot`、`zhipu`、`minimax`、`openai`、`mistral`、`groq`、`cerebras`、`nvidia` | 依据官方文档编写，**未实测**；接入时先跑 providercheck，结果写回预设的 `notes` |

新预设：在 `internal/dialect/presets/` 加 `<code>.json`（文件名 = 供应商 code，后台据此推荐「同名预设」），
`notes` 写清来源与是否实测；`go test ./internal/dialect` 会校验所有预设能被加载。

## 8. 运维

- **每日巡检**：`./scripts/provider-canary.sh`（默认只测 chat / chat_stream / embedding，`full` 测全部 9 项）按各认证报告记录的
  参数（base_url、预设、模型、`key_env`）重测，回写报告并刷新能力矩阵；有能力由通过变为失败时退出码为 2，可接 cron / CI 告警。
  Key 只从环境变量读，没有 Key 的供应商跳过。
- **临时停用 codec**：网关配置 `relay.disabled_codecs`（或环境变量 `UFT_RELAY_DISABLED_CODECS`，逗号分隔，如 `dashscope.tts`）——
  用到它的渠道不参与路由，用于 codec 出问题时不回滚代码即可止血；同类开关 `relay.disabled_endpoints` 按端点下线。
- **排查**：后台请求日志的「尝试轨迹」会显示每次尝试使用的 codec（协议默认透传时不显示）。

- **对账**：worker 每日对账会比较上游返回的 `cost`（OpenRouter 等会给）与网关按成本价算出的金额，偏差 >20% 的渠道记日志
  （`UpstreamCostDrift`），通常是成本价录错或上游调价。
- **回退**：后台「供应商方言 → 历史版本」保留最近 5 个版本，可一键回退；每次保存都记审计日志（`provider_account.dialect`）。
- **Key 安全**：测试用 Key 放 `tests/gateway_py/.env`（已 gitignore）；不要写进方言、命令行或文档。
