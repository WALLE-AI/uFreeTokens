# 运营后台全局助手（数据分析与报表）执行方案

> 日期：2026-10-03
> 关联文档：`运营后台 Agent 模块（Harness 智能体）技术架构设计方案.md`（§19 前端嵌入）、`运营后台 Agent 模块（Harness 智能体）实施方案.md`

**结论：** 删掉 `/agent` 这个独立页面。会话列表、剧本选择、运行指标这三样只在这个页面上有，要先移到右侧的 Dock 里。之后在现有的推理循环、工具注册表、审批机制上加两块能力：数据分析（一个按白名单查询指标的工具，查询结果存成数据集）和报表生成（图表块、报表存档、导出、定时报表）。

下面的方案基于对现有代码的阅读：`nav.ts`、`router.tsx`、`AgentPage.tsx`、`AgentDock.tsx`、`AgentProvider.tsx`、`internal/agent/context.go`、`tools/routes/specs.go`、`admin/stats.go`。

## 一、现状

| 项 | 现状 | 对改造的影响 |
|---|---|---|
| 入口 | 侧栏「智能体」分组下有 运营助手 `/agent`、提案收件箱 `/agent/inbox`、智能作业 `/agent/jobs` | 只删「运营助手」，收件箱和作业页保留 |
| 全局 Dock | `AgentDock` 挂在 `AdminLayout` 里、`<Outlet/>` 外面，用 ⌘J 或顶栏按钮开关，切换路由时 SSE 不断 | 已经具备全局助手的形态，可以直接作为唯一入口 |
| 独立页 `AgentPage` | 只有它有：会话列表（搜索、我的/全部管理员）、剧本选择、运行指标、归档 | 这些要先移到 Dock，再删页面 |
| 指向 `/agent/:id` 的链接 | `AgentDock`、`AgentEmbeds`（2 处）、`InboxPage`、`JobsPage`、`AuditPage` | 需要统一改成「打开 Dock 并定位到会话」 |
| 系统提示 | 定位为「运营智能体」，只覆盖调价、上架、优惠、渠道、元数据 | 要改成平台全局助手 |
| 分析类工具 | 只有 `get_stats_overview`、`get_stats_usage`、`search_request_logs`、`get_channels_health` | 维度和指标不够，没有同比环比、毛利、错误分布，也不能产出图表或报表 |
| 图表 | `components/ui/Charts.tsx` 里只有 `TrendBars`、`ShareBar`，没有图表库 | 需要补折线图、饼图和表格渲染 |

## 二、目标形态

1. **唯一入口是全局 Dock**：任何页面都能用 ⌘J、顶栏按钮或命令面板里的「问智能体」打开。Dock 内可以切换会话、选剧本、展开成宽屏，用宽屏来替代原来的独立页。
2. **全局助手**：自动知道「当前在哪个页面、看什么对象、用了哪些筛选条件」，工具覆盖平台所有可读模块，范围受当前管理员的权限限制。
3. **数据分析**：用自然语言提问，例如「近 30 天收入前 10 的模型和环比」，助手调用分析查询工具，返回带数据来源的结论、表格和图表。
4. **报表生成**：助手把分析结果组装成报表，能保存、分享、导出（CSV、XLSX、Markdown、打印成 PDF），也能用智能作业定时生成（日报、周报）。
5. **防幻觉的硬约束**：图表和报表里的数字只能引用工具返回的数据集（`dataset_id`），不能由模型自己写。

### P2：数据分析能力（后端为主，约 5–7 天）

**方案对比与推荐**

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 不断补 `/stats/*` 端点 | 每种分析需求加一个接口和一个工具 | 工具数量会膨胀，灵活性差 |
| **B. 语义指标层 `query_analytics`** | 指标 × 维度 × 过滤 × 时间粒度都走白名单，服务端拼出参数化 SQL，只读汇总表或日志表 | **推荐**：一个工具覆盖大多数问题，安全可控 |
| C. 只读 SQL 沙箱 | 模型自己写 SQL，用只读角色、statement_timeout、视图白名单兜底 | 风险和审计成本高，暂不做，放到后续版本评估 |

**1. 新增 `internal/admin/analytics.go`**，复用 `stats.go` 里已有的 `sourceFor`（rollup 表与明细表的自动切换）、`whereFor`、`labelGroups`。
- 指标：`requests`、`tokens_in`、`tokens_out`、`revenue`、`cost`、`margin`、`margin_rate`、`error_rate`、`p50_latency`、`p95_latency`、`active_accounts`、`new_accounts`、`wallet_topup`（钱包类指标需要 `account:read`）。
- 维度：`virtual_model`、`channel`、`provider`、`account`、`api_key`、`error_code`、`http_status`、`time`。
- 过滤、粒度、排序：`from`/`to`、各维度的过滤条件、`interval=hour|day|week|month`、`top`、`order_by`。
- 派生计算：`compare_to=previous_period|same_period_last_week|last_month`。服务端算出 `delta`、`delta_pct` 和占比 `share`，避免模型自己算数。
- 硬限制：时间跨度不超过 400 天、结果不超过 5000 行，加 statement_timeout，按每个指标逐一检查权限。
- 路由：`POST /analytics/query`，权限 `observe:read`，写入 `admin_routes.go` 和 `admin_openapi.go`，然后重新生成 `docs/admin-openapi.json` 和前端的 `generated.ts`。

**2. 数据集存储**（迁移 `00037_agent_datasets.sql`）
- 新表 `agent_datasets(id, session_id, tool_call_id, spec jsonb, columns jsonb, rows jsonb, row_count, created_at)`。
- 工具返回给模型的只有：`dataset_id`、列定义、前 20 行预览和汇总统计。完整数据只存在数据集里，这样能控制上下文长度。
- `pgstore` 和 `memstore` 都要实现，`kernel/store.go` 接口加 `SaveDataset`、`GetDataset`。
- 新路由 `GET /agent/datasets/{id}`（会话归属校验同会话详情）、`GET /agent/datasets/{id}/export?format=csv|xlsx`。XLSX 后端用 excelize。

**3. 工具**
- `query_analytics`：绑定 `/analytics/query`。
- `get_dataset`：分页读取数据集剩余的行，供模型深入分析。

**4. 评测**：在 `internal/agent/eval/cases` 里新增 6–10 个分析类用例，例如「上周收入前 5 模型和环比」「错误率突增的渠道」。断言回答里出现的数字都能在数据集里找到。

### P3：报表生成（前后端，约 5–7 天）

**1. 图表块（会话内实时渲染）**
- 新增工具 `render_chart`（`RiskRead`，不绑定路由，在内核本地执行）。参数为 `{dataset_id, type: line|bar|stacked_bar|pie|table|stat, x, y[], series?, title}`。服务端校验 `dataset_id` 属于本会话、列名存在，校验通过后发出新的 SSE 事件 `artifact`，内容为 `{kind: 'chart', dataset_id, spec}`。
- 前端：`AgentProvider` 的 `LiveItem` 加 `{kind: 'artifact'}`；`RunBlock` 和 `runSteps.ts` 渲染新组件 `ArtifactChart.tsx`，数据通过 `GET /agent/datasets/{id}` 拉取，所以图表数字一定来自数据集。卡片上提供「导出 CSV/XLSX」「加入报表」。
- 图表组件：在 `Charts.tsx` 上补 `LineChart`、`PieChart`、`DataTable` 适配。建议手写 SVG，不引入重型依赖；如果要加依赖，选 recharts，约 100KB gzip，需要确认。实现时遵循统一的配色和无障碍规范。

**2. 报表存档**（迁移 `00038_agent_reports.sql`）
- `agent_reports(id, title, owner_admin_id, session_id, job_id, sections jsonb, dataset_ids bigint[], visibility: private|shared, created_at, updated_at)`。
- `sections` 由多个块组成：`markdown`、`chart{dataset_id, spec}`、`table{dataset_id}`、`kpi{dataset_id, metric}`。数据集以快照方式保存，之后数据变化也不会改动已生成的报表。
- 工具 `create_report`：`RiskWrite`，但只写报表、不改业务数据。默认直接执行、不进审批（标记为 `auto_execute`）。需要在 `approval.go` 给 risk 加一个子类型 `artifact_write`，或者用 `RiskRead` 加审计记录。
- 路由：`GET /agent/reports`、`GET /agent/reports/{id}`、`PATCH`（标题、可见性）、`DELETE`、`GET /agent/reports/{id}/export?format=md|xlsx`。XLSX 每个数据集一个 sheet，加一页摘要。
- PDF：前端用打印样式表（`@media print`）配合 `window.print()`，不在后端渲染。

**3. 报表查看入口**（待决，见第五节第 1 点）
- 推荐：在 Dock 里新增「报表」页签，可以列表和预览；全屏模式下按完整版式阅读。深链 `?report=<id>`。

**4. 定时报表**
- 复用 `agent_jobs` 的批处理模式，新增剧本 `playbooks/daily_ops_report.md`、`weekly_revenue_report.md`，要求剧本最后必须调用 `create_report`。
- 运行完成后，报表出现在收件箱（新增一种 `report` 通知条目），也可以在 `JobsPage` 的「查看最近运行」里打开。
- `jobs/triggers.go` 新增 cron 触发器配置（如果目前只有事件触发）。

### P4：收尾（约 2 天）

- 文档：更新 `docs/admin-api.md` 和 openapi；在设计文档 §19.4 里注明「L3 独立页已取消，改为 Dock 宽屏和全屏」。

  - Go：`analytics_test.go`（白名单、权限、compare 计算）、`pgstore_test.go`（datasets、reports）、`loop_test.go`（artifact 事件）。
  - 前端：playwright 冒烟，覆盖「提问、出图、生成报表、导出」。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 模型编造数字 | 图表和报表只能引用 `dataset_id`；派生指标由服务端计算；评测里断言回答中的数字都能在数据集里找到 |
| 大查询拖慢数据库 | 只读白名单 SQL、优先走 rollup 表、statement_timeout、限制时间跨度和行数 |
| 上下文超长 | 工具结果只给模型预览，完整数据放在数据集里，需要时用 `get_dataset` 分页取 |
| 越权查看数据 | 按指标逐一检查权限；数据集和报表按会话及归属管理员做访问控制 |
| 删除页面后旧链接失效 | `/agent/:id` 保留为重定向；统一使用 `?agent=` 深链 |

**排期建议**：P0 和 P1 可以作为第一个 PR，用户能立刻感知到变化，风险也低。P2 和 P3 分别各提一个 PR。
