**方案之外发现并修复的问题**

- **分区边界不是 UTC**：请求日志分区边界按数据库会话时区解释，在北京时区的库上整体偏移 8 小时。现已改为显式 UTC。
- **兜底分区挂载失败**：兜底分区里有数据时，补建对应日期的分区会失败。现在会先把这部分行挪进新分区再挂载。
- **保留期删分区失败**：存在兜底分区时，Postgres 不允许 `DETACH ... CONCURRENTLY`。保留期任务改用普通 `DETACH`。
- **价格本重叠**：历史上同一条价格链的多个版本生效期全部重叠。迁移 00019 先修复这些数据，再加排他约束。

## 0. 结论摘要

整体骨架是健康的：前端全部走统一的 `request()`（`frontend/admin/src/api/client.ts`），无 mock 数据；后端错误信封统一、排序字段白名单化、SQL 全部参数化（未发现注入点）、余额用 int64 微元、单价用 `NUMERIC`/`decimal`、上游密钥信封加密且只回传 `last4`。

但离"可以交给多名运营在生产上用"还有四类硬伤，按严重度排序：

| 级别 | 问题 | 后果 |
|---|---|---|
| **P0 安全** | 单一共享 Bearer Token，无登录/会话/过期/RBAC；审计操作人来自客户端自填 `X-Actor-*` 头 | 审计不可信，令牌泄露即全权限，无法按人追责 |
| **P0 安全** | `base_url` 不校验 + `GET /provider-accounts/{id}/upstream-models` 会用**解密后的上游密钥**请求该地址；`reference-price-lookup` 可请求任意 URL | 持令牌者可把上游 API Key 外带到自己的服务器（SSRF + 凭据泄露） |
| **P1 一致性** | 调价审批 check-then-act 无锁；"最后一个活跃渠道"守卫只锁目标行；上架发布（PublishListing）/ 前端向导导入非原子；审计写在业务事务之外 | 并发下重复发布成本价、模型无可用渠道、半成品模型、审计缺失 |
| **P1 一致性** | `ledger_entries` 唯一约束含可空 `grant_id`（NULL 互不相等）→ 现金流水幂等约束形同虚设；赠金 `ref_id` 为空时自动生成 → 重试会重复发放 | 账务重复入账 |
| **P2 接口设计** | 未知错误一律 400 且透出 Postgres 原文；`GET /virtual-models`、`GET /channels` 按参数返回"单对象或分页"两种形状；PATCH 无乐观锁；多处 100/200 条静默截断；时间全部 UTC 无时区参数 | 前端难以正确处理错误/并发覆盖/数据不全 |
| **P2 性能** | 虚拟模型/渠道全量加载后内存分页；batch-approve 每条跑约 8 条 SQL + 7 天 request_logs 扫描（×100）；统计直扫 request_logs 无汇总表；request_logs 分区只建不删 | 数据量上来后后台不可用、磁盘无限增长 |
| **P3 前端** | 向导每个模型约 5 次请求且非原子；金额/毛利用 JS 浮点计算并作为售价提交；枚举硬编码；本地时间与 UTC 统计混用 | 价格精度误差、与后端 `margin_ratio` 不一致 |

## 1. 现状盘点

### 1.1 鉴权与调用链

```
浏览器 ──(Authorization: Bearer UFT_ADMIN_TOKEN, X-Actor-Name)──▶ Nginx/Vite /admin-api ──▶ cmd/admin :8081
```

- 令牌存在 `sessionStorage`（`src/api/auth.ts:8-9`），登录页用 `GET /audit-logs?limit=1` 校验令牌（`src/api/audit.ts:22`），没有 `/login`、`/me`。
- 后端 `httpx` 中间件常量时间比较令牌（`internal/httpx/middleware.go:71-83`），无限流、无锁定。
- 操作人：`actorIDFromRequest`/`actorNameFromRequest`（`internal/app/admin.go:181-201`）直接信任请求头；审批还会回退到请求体 `decided_by`（`internal/app/pricesync.go:235-240`）。IP 取 `RemoteAddr`，经反代后全是代理地址（`admin.go:204`）。
- 服务器只设置了 `ReadHeaderTimeout`，无 Read/Write/Idle 超时（`cmd/admin/main.go:98-102`），请求体无大小限制（`admin.go:131`）。

### 1.2 接口规模

约 60 个路由，前端调用覆盖率接近 100%（仅 `GET /channels/{id}/price-books`、`POST /providers/{id}/price-observations` 前端未使用）。三种响应形状：

| 形状 | 用于 |
|---|---|
| `{data,total,page,page_size}` 偏移分页 | accounts、api-keys、providers、provider-accounts、virtual-models、channels、price-change-requests、pending-model-listings |
| `{data,next_cursor}` 游标分页 | ledger、audit-logs、request-logs |
| `{data}` 不分页 | credit-grants（硬上限 200）、账户下 api-keys（无上限）、price-sources、fx-rates、price-books |

### 1.3 数据库

pgx v5 + 手写 SQL（`internal/store/postgres.go` 注释提到的 sqlc 目录并不存在），goose 迁移 15 个。领域划分：

- **账户**：accounts ─< account_members >─ users；accounts ─< api_keys；accounts ─ wallets(1:1)
- **目录/路由**：providers ─< provider_accounts ─< provider_keys；virtual_models >─< provider_accounts 经 channels；virtual_models ─ virtual_model_metadata(1:1)
- **定价**：price_books(sell→vm / cost→channel) ─< price_components；fx_rates 独立
- **价格同步**：price_sources ─< price_observations；price_change_requests → channels/price_books；pending_model_listings
- **钱包**：credit_grants、ledger_entries（只追加触发器）、reservations
- **用量**：request_logs（按天分区，无任何 FK，模型按**名称**存）
- **支付/审计**：payment_orders、admin_audit_logs（无 FK、可修改）
- **后台专用**：仅 00015 的索引与 `actor_name` 等列；**没有管理员/角色/会话表**

> 注：根目录《AI 多 Provider API 平台计费与模型路由技术执行方案》§4 的数据模型（`wallet`/`model_pricing.profit_rate`/`provider_api_key` 健康列）是 V1 设计，已与迁移脱节，不应再作为数据模型参考。

| 账务 | C6 唯一约束失效；单式记账，无 journal/transaction_id 聚合同一次结算的多行，无平台对手科目；`bonus_balance` 无 `>= 0`；wallet 与 reservations/credit_grants 汇总无对账约束；钱包/流水无币种列 |
| 外键 | `price_books.created_by`、`price_change_requests.decided_by`、`admin_audit_logs.actor_id` 无 FK（没有管理员表可指）；`evidence`、`allowed_account_ids`、`promotion_ids` 等数组无法 FK |
| 删除语义 | accounts 对 wallets/api_keys/grants CASCADE，对 ledger/reservations/payment_orders RESTRICT，实际不可硬删——应明确"只允许 status=closed"；provider_accounts → provider_keys CASCADE 会静默删除加密密钥 |
| 枚举 | `accounts.tier`、`price_books.tier/currency`、`price_components.meter/service_tier`、`request_logs.status/endpoint/error_code`、`providers.currency`、`virtual_models.family`、审计 action/target_type 均为无 CHECK 的 TEXT；无 `tiers` 表，tier 字符串散落 4 处 |
| 时间列 | providers、provider_accounts、virtual_models、channels、price_components、fx_rates 无 `created_at`；只有 3 张表有 `updated_at`；无乐观锁版本列 |
| 软删除 | 各表 status 取值不一（active/disabled、active/deprecated/hidden、enabled bool…） |
| 反范式 | request_logs.virtual_model、api_keys.allowed_models 存**名称**，模型改名/别名会破坏统计与白名单；`actor_name`/`decided_by_name` 为自由文本 |
| 分区 | 无保留策略、无 DEFAULT 分区；00015 在父表上非 CONCURRENTLY 建索引 |
| 缺表 | 管理员/角色/会话、调账审批、渠道健康历史、用量汇总、任务运行记录、实验、tiers、保存视图/告警等 |

## 3. 执行方案

分 5 个批次，沿用上一份方案的 B 编号（B1~B4 已完成）。每批独立可上线，前后端同批交付。

### B5 安全基线（P0，优先级最高，约 5 人日）

**目标**：有真实管理员身份，审计可信，堵住密钥外带。

1. **管理员账号与会话**（迁移 00016，见 §4.1）
   - 新增 `POST /auth/login`（邮箱+密码，argon2id；可选 TOTP）、`POST /auth/logout`、`GET /me`（返回 `{id,name,email,roles,permissions}`）、`POST /auth/password`。
   - 会话：不透明 token（32 字节随机，库里存 SHA-256），`admin_sessions` 表，默认 12h 滑动过期 / 7 天绝对过期；登出即删行。
   - 登录限流：按 IP + 邮箱在 Redis 计数，5 次失败锁 15 分钟，写 `admin_login_events`。
   - 过渡：保留 `UFT_ADMIN_TOKEN` 作为 break-glass，身份固定为 `system`，并在启动时打 WARN；配置 `UFT_ADMIN_LEGACY_TOKEN_ENABLED=false` 后关闭。
   - 提供 `cmd/admin` 子命令 `create-admin --email --role super_admin` 用于初始化。
2. **RBAC**
   - 角色：`super_admin`、`operator`（目录/渠道/上架）、`pricing`（价格/审批）、`finance`（调账/赠金/账单）、`support`（只读 + 日志）。
   - 权限点粒度 `资源:动作`（如 `wallet:adjust`、`price_change:approve`、`provider_key:write`），路由注册时声明：`r.With(require("wallet:adjust")).Post(...)`。
   - 未授权返回 403 `permission_denied`。
3. **可信审计**
   - 删除 `X-Actor-ID/X-Actor-Name` 读取与请求体 `decided_by` 回退，身份一律来自会话中间件注入的 `ctx`。
   - IP 通过可信代理列表（`UFT_ADMIN_TRUSTED_PROXIES`）解析 `X-Forwarded-For`。
   - 审计增加 `request_id`、`user_agent`、`session_id`、`reason` 列。
4. **SSRF 与密钥**
   - `base_url` 创建/更新时校验：必须 https；主机匹配 provider 级白名单（`providers.allowed_hosts TEXT[]`，默认从官方域名初始化）；解析后拒绝私网/回环/链路本地地址（发请求时在 `net.Dialer.Control` 里再校验一次，防 DNS rebinding）。
   - `base_url` 变更需要 `provider_key:write` 权限并强制审计；变更后 24h 内 upstream-models 需要 super_admin。
   - `reference-price-lookup` 去掉可传入的 URL 参数，改为服务端配置。
   - discovery 在 `s.box == nil` 时返回 503 `kek_not_configured`，不再 panic。
5. **错误与服务器加固**
   - `writeError` 未识别错误 → 500 `internal_error`，消息固定，原文只进日志（带 request_id）；FK 违反映射为 422/409。
   - `http.Server` 设置 Read/Write/Idle 超时；`http.MaxBytesReader` 限 1 MiB（批量导入 4 MiB）；`X-Request-Id` 只接受 `[A-Za-z0-9-]{1,64}`。
6. **前端**
   - LoginPage 改为邮箱+密码，调用 `/auth/login`；启动时 `GET /me` 拉角色，`nav.ts` 与按钮按 `permissions` 显隐（后端仍是最终裁决）。
   - 删除 `X-Actor-Name`；登出调用 `/auth/logout`。
   - 会话 token 仍放 `sessionStorage` + Bearer（不引入 Cookie，避免 CSRF 改造）。

**验收**：伪造头无效；support 角色调用 `wallet/adjust` 得到 403；把 `base_url` 改为 `http://127.0.0.1` 或非白名单域名返回 422；无 KEK 时 upstream-models 返回 503；DB 断开时返回 500 且无 SQL 文本。

### B6 数据一致性（P1，约 4 人日）

1. **审计入事务**：`RecordAudit` 改为接收 `pgx.Tx`；`patchRow`、钱包、赠金、审批、发布等写操作在同一事务内写审计，审计失败即回滚。审计 `before` 从 `FOR UPDATE` 读出的旧行取（修复 sell/cost/FX/metadata 的 `before=nil`）；价格观测 ingest 触发自动发布时写 `actor=system` 的审计。
2. **调价审批加锁**：approve/reject 以 `SELECT ... FROM price_change_requests WHERE id=$1 FOR UPDATE` 开头，状态判定、发布成本价本、写 decision 在同一事务；并以 `UPDATE ... WHERE status='pending'` 作为二次保护。
3. **最后活跃渠道守卫**：禁用渠道时先 `SELECT id FROM channels WHERE vm_id=$1 FOR UPDATE`（锁住该模型下所有渠道行）再计数。
4. **PublishListing 与批量导入原子化**：将 listing 发布的多步放进单事务；新增 `POST /provider-accounts/{id}/import-models`（见 B7），替换前端向导逐条调用。
5. **账务幂等**（迁移 00017）：
   - `ledger_entries` 唯一约束改为 `UNIQUE NULLS NOT DISTINCT (ref_type, ref_id, type, balance_kind, grant_id)`（PG15+，当前 PG16）。上线前先跑重复检测 SQL，有历史重复则先人工处理。
   - `credit_grants` 增加 `ref_id`，并建 `UNIQUE (account_id, source, ref_id)`；API 改为 `ref_id` 必填（前端自动生成 UUID，重试复用）。
   - `payment_orders.external_id` 加 `UNIQUE (channel, external_id)`。
6. **乐观锁**：providers、provider_accounts、provider_keys、virtual_models、channels、accounts、price_sources 增加 `updated_at` + `version INT`（迁移 00018）。详情接口返回 `ETag: W/"<version>"`，PATCH 要求 `If-Match`，不匹配时 412 `version_conflict`；前端弹出"数据已被他人修改，是否刷新"。过渡期缺失 `If-Match` 只打 WARN，一个版本后改为 428。
7. **PATCH 回读失败**：更新与回读放在同一事务内，或回读失败时返回 200 + 已提交数据的最小体。
8. **价格本完整性**（迁移 00019）：`CHECK (effective_to IS NULL OR effective_to > effective_from)`；引入 `btree_gist`，对 sell（vm_id, tier）和 cost（channel_id）加 `EXCLUDE USING gist (... WITH =, tstzrange(effective_from, effective_to) WITH &&)`。发布新价格本时在同一事务里把上一本的 `effective_to` 设为新本的 `effective_from`。`price_components` 补 `unit_price >= 0`、阶梯与时间窗 CHECK，唯一约束改 `NULLS NOT DISTINCT`。
9. **撤销上游 Key 清冷却**：revoke 事务提交后删除 Redis 冷却键（失败只记日志，冷却自带 TTL）。
10. **防篡改**：给 admin_audit_logs、price_observations 加与 ledger 相同的禁止 UPDATE/DELETE 触发器；三张表都加 `BEFORE TRUNCATE` 语句级触发器。

**验收**：并发测试——同一变更请求并发 approve 10 次只产生 1 个价格本；并发禁用同一模型最后两个渠道只成功 1 个；同一 `ref_id` 赠金重试 3 次只入账 1 次；重叠生效期插入被数据库拒绝。

### B7 接口规范化与缺失接口（P2，约 5 人日）

1. **统一约定**（写入 `docs/admin-api.md` 并生成 OpenAPI 3.1，路由注册处用注解或手写 yaml，CI 做前端类型生成 `openapi-typescript` → 替代手写 `types.ts` 的接口部分）：
   - 写接口统一返回资源对象；动作接口（approve/revoke/dismiss）返回更新后的资源。
   - 所有列表返回 `{data, total?, page?, page_size?, next_cursor?, truncated?}` 之一；超上限 `limit` 截到上限。
   - 统一参数解析器：非法枚举/布尔/数字 → 400 `invalid_request` 并给出 `param`。
   - 金额字段统一 `*_micro`，请求体的 `amount` 改名 `amount_micro`（旧字段兼容一个版本）；JSON 统一 snake_case（`ModelScores`、观测 spec 的 PascalCase 在序列化层转换）。
   - 时间参数支持 `tz`（IANA 名，默认 `Asia/Shanghai`），统计分桶用 `date_trunc(interval, created_at AT TIME ZONE $tz)`；`SetFXRate` 生效日期用 DB `CURRENT_DATE`。
   - POST 支持 `Idempotency-Key`（Redis 存 24h：key → 响应摘要）。
2. **拆分双形态接口**：`GET /virtual-models/lookup?name=`、`GET /channels/lookup?vm_id&pa_id&upstream_model`；旧的带参数形态保留一个版本并加 `Deprecation` 头。
3. **下推到 SQL**：虚拟模型、渠道列表的过滤/排序/分页（margin、missing 这类派生条件用 LATERAL 子查询或物化到 B8 的 `catalog_price_view`）；`/todo-counts` 改为单条聚合 SQL。
4. **子资源分页**：`GET /providers/{id}/accounts`、`GET /virtual-models/{id}/channels`、credit-grants、账户 api-keys、price-sources 支持分页；详情中的内嵌列表加 `truncated`。
5. **新增接口**：

|---|---|---|
| `GET /meta/enums` | tier、protocol、meter、unit、capabilities、change_status、ledger_type、grant_source、fetcher 等字典 | `types.ts`/`PublishListingDrawer.tsx` 硬编码 |

6. **batch-approve**：先用一条 SQL 批量取出候选请求（`WHERE id = ANY($1) FOR UPDATE`），影响评估的 7 天用量改为一次按 channel_id 分组查询（B8 之后读汇总表），逐条事务审批。

**验收**：OpenAPI 覆盖全部路由且 CI 校验与实现一致；前端 `types.ts` 中接口类型由生成代码替换；上述新接口均有 HTTP 测试。

### B8 性能与数据生命周期（P2，约 4 人日）

1. **用量汇总表** `usage_hourly`（迁移 00020）：维度 `(bucket_hour, account_id, api_key_id, virtual_model_id, channel_id, provider_key_id, status_class)`，指标 requests、tokens、list/charged/cost_micro、错误数、延迟直方图（固定分桶数组，用于近似 P50/P95）。worker 每 5 分钟 upsert 最近 2 小时。overview/usage/影响评估 > 48h 的窗口读汇总表，≤ 48h 读原表。

9. 类型：接口类型改由 OpenAPI 生成，手写 `types.ts` 只保留 UI 派生类型。

## 4. 数据库变更清单

所有迁移遵循：Up/Down 成对；生产大表索引用 `CREATE INDEX CONCURRENTLY`（goose 用 `-- +goose NO TRANSACTION`）；约束先 `NOT VALID` 再 `VALIDATE CONSTRAINT`，避免长时间锁表。

### 4.1 00016_admin_identity.sql

```sql

  email           CITEXT NOT NULL UNIQUE,
  name            TEXT   NOT NULL,
  password_hash   TEXT   NOT NULL,             -- argon2id

CREATE TABLE admin_user_roles (
```

### 4.3 00018_optimistic_locking.sql

对 providers、provider_accounts、provider_keys、virtual_models、channels、accounts、price_sources：

```sql
ALTER TABLE <t> ADD COLUMN IF NOT EXISTS created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
                ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
                ADD COLUMN IF NOT EXISTS version    INT         NOT NULL DEFAULT 1;
```

`patchRow` 统一 `UPDATE ... SET ..., version = version + 1, updated_at = now() WHERE id = $1 AND version = $2`，影响行数为 0 → 412。钱包沿用 `expected_cash_balance_micro`，并让现有 `wallets.version` 真正递增。

同时把 provider_accounts → provider_keys 的 `ON DELETE CASCADE` 改为 `RESTRICT`（不允许静默删除加密密钥）。

## 5. 排期、依赖与风险

| 批次 | 内容 | 依赖 | 估算 |
|---|---|---|---|
| B5 | 管理员身份、RBAC、可信审计、SSRF、错误映射 | 00016 | 5 人日 |
| B6 | 事务化审计、并发锁、账务幂等、乐观锁、价格本约束 | 00017~00019，B5（审计 actor） | 4 人日 |
| B7 | 接口规范化、OpenAPI、新接口 | B6（import-models 依赖原子化） | 5 人日 |
| B8 | 汇总表、分区保留、索引、缓存 | 00020~00021 | 4 人日 |
| B9 | 前端配套 | 与各批次同步 | 4 人日 |

**建议顺序**：B5 → B6 并行准备 B8 的迁移 → B7 → B8；B9 跟随各批次交付。

**主要风险**：

1. **历史数据违反新约束**：00017、00019 上线前必须跑检测 SQL；所有新约束以 `NOT VALID` 加入，清洗完再 `VALIDATE`。
2. **旧令牌切换**：break-glass 令牌保留一个版本，前端同时支持两种登录方式，确认所有运营已建账号后关闭。
3. **If-Match 强制**：先 WARN 后强制，避免老前端缓存导致全部 PATCH 失败。
4. **request_logs 大表索引与 DEFAULT 分区**：DEFAULT 分区存在时新建分区会扫描 DEFAULT 分区校验，需保持其为空（监控 + 告警）。
5. **int64 字符串化**：前后端需同版本切换，否则金额显示错误；建议放在 B9 最后，并用 `Accept` 版本头兜底。

## 6. 测试补齐

- **HTTP 测试补全**：PATCH provider-accounts/accounts/price-sources、PUT metadata、dismiss、fx-rates/latest、两个 price-books、upstream-models（含无 KEK）。
- **鉴权矩阵**：每个路由 × 每个角色的 200/403 表驱动测试（从路由注册表自动生成）。
- **并发**：双重审批、最后渠道竞态、赠金重试、乐观锁冲突。
- **错误映射**：DB 断开 → 500 不含 SQL；FK 违反 → 422。
- **SSRF**：私网 IP、DNS rebinding、非白名单域名。
- **分页边界**：超上限 limit、非法 cursor、非法枚举。
- **统计口径**：固定夹具验证 overview/usage 数值；汇总表与原表结果一致（误差仅来自 P95 近似）。
- **时区**：`tz=Asia/Shanghai` 下跨零点的分桶。
- **迁移**：每个新迁移 Up → Down → Up 可重复执行。
