# 外部数据采集模块（价格情报与评测榜单）技术方案

> 目标：在后台新增统一的"外部数据采集"能力，服务两类场景：
> 1. **价格情报**（服务 admin 运营后台）：抓取各大模型提供商的真实价格、限时优惠、免费模型信息，用于成本价维护、选品、促销决策。
> 2. **评测榜单**（服务 frontend/web 排行榜/基准测试页）：从权威公开评测榜单拉取数据，自动填充 `benchmarks` / `benchmark_results` 与 `virtual_model_metadata.scores`。

---

## 0. 结论速览

- **不要从零做"爬虫"**。现有代码已经有一半：
  - `internal/pricesync` 已实现 `Fetcher` 接口与 OpenRouter / LiteLLM / HTML 表格三种抓取器、`Engine.Ingest`（校验→比对→策略→自动发布或生成 `price_change_requests`）、新模型发现（`pending_model_listings`）。
  - `migrations/00024_benchmarks.sql` + `internal/benchmarks` + admin 录入页已经能承载榜单数据（`benchmark_runs.origin='import'` 就是为导入预留的）。
  - `cmd/worker` 有 `jobRunner` + `job_runs` 记录。
- **真正缺的是三件事**：
  1. **调度器**：`price_sources.schedule` 没人读，抓取器没有被周期调用（`pricesync.go` 包注释已写明）。
  2. **优惠/免费信息的数据实体与审核流**：现在只有 `promotions`（我方生效的促销），没有"上游市场上的优惠情报"。
  3. **评测榜单抓取器 + 模型名映射**：各榜单模型命名不一致，这是榜单接入的最大工作量。
- 方案：新增 `internal/datasync`（通用调度 + 来源注册 + 运行记录），价格侧复用 `pricesync`，新增 `internal/benchsync` 做榜单抓取与映射；worker 增加一个 `datasync_tick` 任务驱动全部来源。
- 预计 **15～20 人日**，分 4 个阶段（§7），阶段 1 结束即可让价格同步与 LMArena/Epoch 两个榜单自动跑起来。

## 1. 总体架构

```
                    ┌──────────────── cmd/worker ────────────────┐
                    │ jobRunner.run("datasync_tick", 1m, ...)     │
                    └──────────────────┬─────────────────────────┘
                                       │ 选出到期来源（next_run_at <= now）
                                       │ pg_try_advisory_xact_lock(source_id) 防多副本重复跑
                                       ▼
                         internal/datasync.Scheduler
                                       │ 按 source.kind/fetcher 分发
            ┌──────────────────────────┼───────────────────────────┐
            ▼                          ▼                           ▼
   pricesync.Fetcher           offers.Fetcher               benchsync.Fetcher
   (价格：OpenRouter/          (优惠/免费：OpenRouter       (榜单：LMArena/Epoch/
    models.dev/LiteLLM/         :free、厂商定价页"限时"      AA/SWE-bench/OpenCompass
    官方定价页/AA)              文案、公告 RSS)              /SuperCLUE/...)
            │                          │                           │
            ▼                          ▼                           ▼
   price_observations          offer_observations          benchmark_snapshots(原始)
   → Engine.Ingest             → upstream_offers 情报库     → 归一化行 → 模型名映射
   → price_change_requests     → 运营一键转 promotions      → benchmark_runs(import, 草稿)
     / 自动发布成本价                                        → 发布 → scores 投影
            │                          │                           │
            └──────────── admin 运营后台审核 / 看板 ───────────────┘
                                                                    ▼
                                                  gateway /v1/benchmarks, /v1/catalog
                                                  → frontend/web 排行榜/基准测试页
```

### 1.1 通用原则

| 原则 | 做法 |
|---|---|
| 数据源优先级 | 官方 API / 公开数据集 > 静态 HTML > 需 JS 渲染的页面（headless）> LLM 抽取。能用结构化数据绝不爬页面 |
| 原始证据留存 | 每次抓取存原始内容（或 hash + 截断正文）+ URL + 时间，任何上线数据都能追溯到证据 |
| 变化才处理 | `ETag` / `If-Modified-Since` + `last_content_hash`，内容没变直接跳过，不写观测 |
| 异常即熔断 | 解析结果行数比上次骤降 > 50%、价格变化 > 阈值、映射命中率骤降 → 本次视为失败，不入库，告警。页面改版是常态，宁可停也不能写脏数据 |
| 人在回路 | 价格：小幅变化可自动发布成本价（沿用 `DecidePolicy`），售价永远人工；优惠：只进情报库，不自动生效；榜单：可信来源 + 映射完整时可自动发布，否则进草稿 |
| 合规 | 遵守 robots.txt、每域限速（默认 ≥ 10s/请求）、明确 UA（`uFreeTokensBot/1.0 (+联系方式)`）；每个来源登记许可证与署名要求，前端必须展示来源与链接（§4.3） |

## 2. 通用调度层 `internal/datasync`

### 2.1 数据模型（新迁移 `00029_datasync.sql`）

不另起"来源表"，而是**把 `price_sources` 泛化为 `data_sources`**（价格、优惠、榜单共用一套调度、运行记录、告警）：

```sql
ALTER TABLE price_sources RENAME TO data_sources;
ALTER TABLE data_sources
  ADD COLUMN domain        TEXT NOT NULL DEFAULT 'price'
        CHECK (domain IN ('price','offer','benchmark','fx')),
  ADD COLUMN name          TEXT NOT NULL DEFAULT '',
  ADD COLUMN license       TEXT,            -- CC-BY-4.0 / Apache-2.0 / proprietary-internal / unknown
  ADD COLUMN attribution   TEXT,            -- 前端必须展示的署名文案
  ADD COLUMN public_display BOOLEAN NOT NULL DEFAULT false, -- 许可证是否允许对外展示
  ADD COLUMN next_run_at   TIMESTAMPTZ,
  ADD COLUMN last_run_at   TIMESTAMPTZ,
  ADD COLUMN last_error    TEXT,
  ADD COLUMN consecutive_failures INT NOT NULL DEFAULT 0,
  ADD COLUMN http_etag     TEXT,
  ADD COLUMN http_last_modified TEXT;
-- schedule 沿用现有 TEXT 列，约定为 Go duration（"6h"、"24h"），不引入 cron 库
-- kind 的 CHECK 增加 'headless'、'llm_extract'
-- 为兼容现有代码，可建 VIEW price_sources AS SELECT ... WHERE domain='price'，或一次性改代码引用

CREATE TABLE data_source_runs (
  id BIGSERIAL PRIMARY KEY,
  source_id BIGINT NOT NULL REFERENCES data_sources(id),
  started_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at TIMESTAMPTZ,
  status TEXT NOT NULL CHECK (status IN ('running','ok','unchanged','failed','circuit_open')),
  items_fetched INT, items_changed INT,
  content_hash BYTEA,
  error TEXT,
  detail JSONB
);
```

### 2.2 调度器

- worker 新增 `jobs.run("datasync_tick", time.Minute, scheduler.Tick)`，和现有任务同一风格。
- `Tick`：`SELECT ... FROM data_sources WHERE enabled AND (next_run_at IS NULL OR next_run_at <= now()) ORDER BY next_run_at LIMIT N`，逐个 `pg_try_advisory_xact_lock(hashtext('datasync:'||id))`，拿到锁才跑——worker 多副本安全（补上 §7.16 设计里"cron + PG advisory lock"）。
- 失败退避：`next_run_at = now() + min(schedule * 2^failures, 24h)`；连续失败 ≥ 3 次或 `last_success_at` 超过 3 个周期 → 打 `alert=true` 日志 + Prometheus 指标 `uft_datasync_source_stale{source}`。
- 每域限速：进程内 `map[host]*rate.Limiter`。
- HTTP 客户端复用 `internal/admin/urlpolicy.go` 的 URL 策略（防 SSRF：来源 URL 由运营配置）。
- admin 提供 "立即运行"（把 `next_run_at` 置为 now）和运行历史。

### 2.3 Fetcher 注册

```go
// internal/datasync
type Fetcher interface {
    Fetch(ctx context.Context, src Source, prev FetchState) (Result, error)
}
type Handler interface { // 每个 domain 一个：price→pricesync.Engine，offer→offers，benchmark→benchsync
    Handle(ctx context.Context, src Source, res Result) (RunStats, error)
}
var registry = map[string]Fetcher{ "openrouter": ..., "modelsdev": ..., "lmarena_hf": ..., }
```

现有 `pricesync.Fetcher` 用一个适配器包进来即可，不改其内部。

## 3. 场景一：价格情报（admin）

### 3.1 价格数据源

| 级别 | 来源 | 获取方式 | 覆盖 | 说明 |
|---|---|---|---|---|
| L2 官方 | OpenAI、Anthropic、Google Gemini、xAI、Mistral 定价页 | HTML（部分有 markdown 版文档页） | 海外主流 | 用已有 `HTMLFetcher` + 每家一份选择器配置；JS 渲染页走 headless（阶段 3） |
| L2 官方 | DeepSeek、月之暗面 Kimi、智谱 BigModel、阿里云百炼、火山方舟（豆包）、腾讯混元、百度千帆、MiniMax、阶跃星辰、硅基流动 | HTML / 文档页 | 国内主流 | 国内厂商常有阶梯价（按输入长度）、缓存价、错峰价，`PriceSpec` 的 input-size tiers / time windows 已能表达 |
| L4 聚合 | **OpenRouter** `GET /api/v1/models` | API，无需 key（**已实现**） | 300+ 模型 | 含 `:free` 免费变体；价格是 OpenRouter 售价，不完全等于官方 |
| L4 聚合 | **models.dev** `https://models.dev/api.json` | 公开 JSON，开源 | 200+ 提供商、按提供商分价 | 含 cache read/write、上下文、发布日期、open_weights；国内厂商覆盖较好，**建议新增** |
| L4 聚合 | **LiteLLM** `model_prices_and_context_window.json` | GitHub JSON（**已实现**） | 广 | 社区维护，更新略滞后 |
| L4 聚合 | Artificial Analysis 免费 API | API key，100 次/天 | 主流 | 价格可做交叉校验；许可证限制见 §4.3 |
| L1 账单 | 各上游账号的账单/用量 API | API | 我方实际成本 | 最"真实"的价格（含我方折扣），阶段 4 再做 |

**"真实价格"的口径**：以 L2 官方价为准，L4 只做交叉校验和兜底；L2 与 L4 差异 > 5% 时进人工审核（`Engine.Ingest` 已有简化版冲突检测）。L1 账单价用于核对我方实际成本与挂牌成本价的偏差。

### 3.2 优惠 / 免费模型情报（新增）

现有 `promotions` 表表示**我方生效的促销**，不适合存"市场上看到的优惠"。新增情报库：

```sql
CREATE TABLE upstream_offers (
  id BIGSERIAL PRIMARY KEY,
  source_id BIGINT REFERENCES data_sources(id),
  provider_code TEXT NOT NULL,          -- deepseek / openrouter / siliconflow ...
  upstream_model TEXT,                  -- NULL = 账号级/全场优惠
  channel_id BIGINT REFERENCES channels(id), -- 映射到我方渠道（可空）
  offer_type TEXT NOT NULL CHECK (offer_type IN
     ('free_model','discount','off_peak','free_quota','new_user_credit','price_cut')),
  discount_ratio NUMERIC(6,5),          -- 0.5 = 五折；free_model 为 0
  quota JSONB,                          -- 免费额度：{tokens: 1000000, period: "once|day|month"}
  limits JSONB,                         -- 免费版限制：RPM/RPD、上下文缩水等
  starts_at TIMESTAMPTZ, ends_at TIMESTAMPTZ,  -- 限时优惠的时间窗
  conditions TEXT,                      -- 原文条件摘要
  evidence_url TEXT NOT NULL, evidence_excerpt TEXT,
  fingerprint BYTEA NOT NULL UNIQUE,    -- provider+model+type+窗口 的 hash，去重
  status TEXT NOT NULL DEFAULT 'new' CHECK (status IN ('new','confirmed','ignored','expired','adopted')),
  adopted_promotion_id BIGINT REFERENCES promotions(id),
  first_seen_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_seen_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**识别方式**（按可靠度）：

1. **结构化**：OpenRouter `pricing.prompt == "0" && pricing.completion == "0"`（含 `:free` 后缀）→ `free_model`；models.dev / 硅基流动 价格为 0 的模型 → `free_model`。
2. **价格观测推导**：`price_observations` 中某模型新价格 < 旧价格 × 0.8 → 生成 `price_cut` 候选；降为 0 → `free_model` 候选。
3. **文案抽取**：官方定价页 / 公告页 / RSS（OpenAI changelog、Anthropic news、DeepSeek/智谱/百炼公告）中命中关键词（"限时""免费""折""off-peak""discount""free tier"）的段落，交给**我方网关上的低价模型**做结构化抽取（输出上表字段的 JSON，带原文片段），**一律 `status='new'` 待人工确认**，不自动生效。
4. **过期**：每次 tick 把 `ends_at < now()` 的置为 `expired`；连续 N 次抓取不再出现的 `free_model` 也置为 `expired`（免费模型常不打招呼下线）。

**运营动作**：在"优惠雷达"页确认后一键"采用"→ 生成一条 `promotions`（`side='cost'`，`cost_free`/`cost_discount`，时间窗带入），可选同时生成 `side='sell'` 的对外让利；`adopted_promotion_id` 回填。

### 3.4 免费模型直通待上架（迁移 00030）

§3.2 的"采用为促销"不会新建渠道和虚拟模型。所以上架一个免费模型原本要走三步：先建渠道，再建虚拟模型，最后回到优惠雷达采用。现在改为：

1. **观测带模型参数**：`Observation.Meta`（`pricesync.ModelMeta`）由 OpenRouter、models.dev、LiteLLM 解析器填充，包括展示名、类型、上下文、最大输出、能力、输入/输出模态。参数不参与 `spec_hash`。写入候选的 `pending_model_listings.observed_meta` 列，上架表单据此预填；后来的观测如果没带参数，不会覆盖已有参数。
2. **免费模型自动进待上架**：`detect_offers` 识别出 `free_model` 后，执行 `Engine.UpsertFreeListing`，写入一条 `origin='free_offer'`、`offer_id` 指向该情报的候选。
   - 这一步不受 `discover_listings` 开关限制。
   - 厂商映射顺序：先用来源绑定的供应商，再查 `provider_code_map`（如 `{"siliconflow-cn": "siliconflow"}`），最后按同名 `providers.code` 查找。平台没有该供应商时只保留情报。
   - 平台上已有该模型的渠道时不建候选。
3. **一键上架**（`POST /pending-model-listings/{id}/publish`）：**虚拟模型名 = 上游原始模型名**，不可修改，请求里的 `virtual_model.name` 会被忽略。
   - **没有同名虚拟模型**：新建虚拟模型。免费模型成本为 0，售价 = 0 × (1 + 加价率) = 0，用户免费调用，此时不需要汇率。
   - **已有同名虚拟模型且在用**：不新建，只在它下面新增渠道并写成本价，售价不变。
   - **同名虚拟模型已废弃**（比如上次免费结束被系统废弃）：重新启用，并按本次观测重新定价。
   - 列表接口返回 `existing_virtual_model_id/status`，供表单提前提示会走哪种情况。
   - 上架后，免费候选关联的情报会被标为 `confirmed`。
4. **生命周期**：每次抓取后执行 `Engine.SyncFreeListings`。判定条件是：情报已过期，并且同一厂商 + 模型没有其它仍有效的免费情报。满足条件时：
   - 待处理的候选置为 `expired`；上游重新免费时自动回到 `pending`；
   - 已上架的停用渠道。如果虚拟模型是候选新建的、且已没有其它可用渠道，同时标为 `deprecated`；挂到已有虚拟模型的只停用渠道。
   - 每条候选只处理一次（记录 `retired_at`），运营手动恢复后不会再被停掉。

运营流程：优惠雷达卡片点"去上架"，或在待上架页按"免费模型"筛选，进入已预填的上架表单，确认后完成上架。"采用为促销"只保留给 `discount`、`off_peak` 这类限时折扣使用。

| **Scale SEAL Leaderboards** | 多项私有评测 | 页面抓取 | 需核实 |
| **MTEB** | 向量模型（embeddings 类目） | HF `mteb/leaderboard`，结果仓库 `embeddings-benchmark/results` | Apache-2.0 |
| **Design Arena** | 设计/前端生成（`scores.design_arena.*` 已接线） | 页面抓取 | 需核实 |

> 不建议接入：HF Open LLM Leaderboard（已于 2025 年停更）；OpenRouter Rankings（反映用量热度而非质量，且我方排行榜已基于自身用量数据 `internal/rankings`）。

**最小可用组合建议**：LMArena（主观体验）+ Epoch（客观基准，含 SWE-bench/GPQA/Aider/Terminal-Bench）+ OpenCompass（中文与国产模型权威）。三者许可都相对清楚（OpenCompass 需授权），覆盖"综合 / 编程 / 推理 / 中文"四个维度。

### 4.2 数据流

```
fetch（parquet/CSV/JSON/HTML）
  → benchmark_snapshots（原始文件 hash + 存储位置，内容未变则 unchanged）
  → 解析器：按来源产出 []NormalizedRow{benchmark_slug, model_label, score, extra{rank, ci, votes, category}}
  → 模型名映射（§4.4）
  → 为每个 benchmark 生成 benchmark_runs(origin='import', published=false) + benchmark_results
  → 发布判定：来源可信 && 映射率 >= 80% && 无异常（Top10 中 >3 个模型分数波动 > 10%）
        是 → 自动 PublishBenchmarkRun
        否 → 留草稿，admin "榜单导入" 页人工检查后发布
  → scores 投影：按 score_projections 规则把指定 benchmark 的分数写入
     virtual_model_metadata.scores（供 /v1/catalog、排行榜散点图使用）
```

**schema 调整（新迁移）**：

- `benchmarks.category` 的 CHECK 扩展：增加 `general`（综合/Arena）、`coding`、`chinese`、`embedding`（或直接把 CHECK 改为查表 `benchmark_categories`，避免以后反复改约束）。
- `benchmarks` 加 `source_id BIGINT REFERENCES data_sources(id)`、`external_key TEXT`（如 `lmarena:text_style_control:overall`），一个来源可派生多个 benchmark。
- `benchmark_results.extra` 约定字段：`rank`、`rank_ub`、`ci_low/ci_high`、`votes`、`raw_label`、`license`。Elo 分数直接放 `score`，`benchmarks.metric_name='Elo'`、`higher_is_better=true`。
- 新表 `score_projections(benchmark_id, score_key)`：如 `lmarena-text → arena_elo`、`epoch-swe-bench-verified → swe_bench_verified`；`internal/admin/scores.go` 的白名单相应扩充。投影写入时在 scores 里一并记 `_sources: {key: {source, run_id, at}}`，便于追溯。

### 4.3 许可与署名（必须做）

- `data_sources.public_display=false` 的来源（Artificial Analysis 免费档、未获授权的 OpenCompass/SuperCLUE）**只能在 admin 显示**；`/v1/benchmarks`、`/v1/catalog` 输出时按此过滤（公开接口查询加条件，scores 投影只投影可公开来源）。
- 公开接口每个 benchmark 带 `source_name`、`source_url`、`license`、`updated_at`（`benchmarks` 表已有 source_name/url），前端在榜单卡片、散点图图例下展示 "数据来源：LMArena (CC BY 4.0)，更新于 …"。
- 现有 `scores` 白名单里的 `intelligence_index / coding_index / agentic_index` 命名与 Artificial Analysis 指数一致——**如果这些分数原本是从 AA 人工抄录的，对外展示同样有授权风险**，需要业务确认：购买 AA 商业授权，或改用自算综合指数（例如基于 Epoch + LMArena 的加权分，公式公开）。

### 4.4 模型名映射（最大工作量）

各榜单命名示例：`claude-opus-4-1-20250805-thinking-16k`、`GPT-5 (high)`、`Qwen3-Max-Preview`、`deepseek-v3.1-terminus`。处理方式：

```sql
CREATE TABLE model_aliases (
  source_kind TEXT NOT NULL,          -- lmarena / epoch / opencompass / ... ，'*' = 全局
  external_label TEXT NOT NULL,       -- 原始名
  virtual_model_id BIGINT REFERENCES virtual_models(id),  -- NULL = 确认"平台未上架/忽略"
  variant TEXT,                       -- thinking / high / 16k 等推理档位
  method TEXT NOT NULL CHECK (method IN ('exact','normalized','fuzzy','manual')),
  confidence NUMERIC(4,3),
  confirmed BOOLEAN NOT NULL DEFAULT false,
  PRIMARY KEY (source_kind, external_label)
);
```

匹配流程：
1. 精确：`virtual_models.name` / `aliases` / `metadata.display_name`。
2. 归一化：小写、去日期后缀（`-20250805`、`-0902`）、去厂商前缀（`anthropic/`）、统一分隔符、把 `(high)` / `-thinking` 抽到 `variant`。
3. 模糊：同厂商内做 token Jaccard / 编辑距离，置信度 < 0.9 的标 `confirmed=false` 待人工确认。
4. 未上架的模型照样入 `benchmark_results`（`virtual_model_id` 为空，`model_label` 展示原名）——现有表结构已支持；前端对未上架模型不显示"立即使用"按钮。
5. 同一模型多个推理档位：取运营指定的"代表档位"投影到 scores（默认取最高分档位，并在 extra 标注）。

admin "模型映射工作台"：按来源列出未确认映射，一键选择虚拟模型 / 标记忽略；确认后的映射对后续所有抓取生效（这也给"新模型发现"提供线索：榜单出现但平台未上架的热门模型 → 提示运营上架）。

### 4.5 frontend/web 改造

- `BenchmarksPage.tsx`：数据已经来自 `/v1/benchmarks`，导入的 run 发布后自动出现；需补：来源署名、更新时间、`category` 新分类的 Tab、Elo 类指标的展示（显示置信区间与票数，无成本/耗时列时隐藏列）。
- `RankingsPage.tsx` 的"基准跑分"板块：散点图 Y 轴支持切换 `arena_elo` / `swe_bench_verified` / `gpqa_diamond` / 综合指数（都来自 `scores`）；新增"权威榜单"Tab：LMArena Top N、中文榜（OpenCompass）。
- 模型详情页：新增"评测成绩"卡片（该模型在各 benchmark 的分数与排名），需要 gateway 加 `GET /v1/models/{name}/benchmarks`（按 `virtual_model_id` 查已发布 run）。
- `data/models.ts` 的 `INITIAL_MODELS` 硬编码 scores 在接入后应只作离线兜底，不再作为数据源。

## 5. 关键实现要点

| 问题 | 方案 |
|---|---|
| 解析 Parquet（LMArena） | Go 用 `github.com/parquet-go/parquet-go` 直接读；或用 HF 的 datasets-server `/rows` JSON 接口免解析（有分页上限，`latest` split 体量小可用） |
| JS 渲染页面（部分官方定价页、OpenCompass、SuperCLUE） | 先找页面背后的 JSON 接口（浏览器 Network 面板），绝大多数都有；实在不行再引入 chromedp，放独立 worker 容器（镜像带 Chromium），不污染主 worker |
| 页面改版导致解析失败 | 解析器输出做"形状校验"（必需字段、行数下限、分数范围），不通过即 `failed` 不入库；每个来源保留 fixture 测试（沿用 pricesync 测试只喂 httptest fixture 的做法，CI 不访问外网） |
| LLM 抽取的可信度 | 只用于优惠文案与无结构定价页；输出必须带原文片段，校验数值能在原文中找到，否则丢弃；永远进人工审核 |
| 多副本 worker | `pg_try_advisory_xact_lock` 按来源加锁 |
| 汇率 | 增加 `fx` 域来源（如中国银行外汇牌价 / ECB 参考汇率），每日写 `fx_rates`，比价看板统一折算 CNY |
| 可观测性 | `observability/metrics.go` 增加 `uft_datasync_runs_total{source,status}`、`uft_datasync_last_success_timestamp{source}`、`uft_datasync_items_changed{source}` |

## 8. 需要业务确认的决策

1. **Artificial Analysis 数据能否对外展示**：免费档条款禁止再分发。选项：购买商业授权 / 仅内部参考 + 对外用自算指数。这也影响现有 `intelligence_index` 等 scores 键的数据来源。
2. **OpenCompass、SuperCLUE 是否发函申请授权**：未授权前对外只显示排名 + 跳转链接，或完全不展示。
3. **价格自动发布阈值**：沿用 `DecidePolicy` 现有阈值，还是对抓取来源更保守（例如 L4 来源永不自动发布，只有 L2 官方源 ±5% 内自动）。
4. **榜单自动发布**：可信来源（LMArena/Epoch）映射率 ≥ 80% 自动发布，还是一律人工发布。
5. **是否引入 headless 浏览器**（多一个带 Chromium 的容器镜像）。
6. **未上架模型是否出现在公开榜单**：建议出现（榜单完整性），但不可点击购买。

### 9.1 与方案的差异

| 方案 | 实际 | 原因 |
|---|---|---|
| `price_sources` 改名为 `data_sources` | 保留表名，加 `domain` 等列 | 避免牵动现有价格同步代码、审计记录与前端；语义上已是通用数据源表 |
