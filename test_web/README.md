# test_web

手工联调用的两个页面，不是生产管理后台。用来验证"管理员接入一个真实上游
（比如 SiliconFlow）→ 拉取它支持的模型 → 导入 → 用户端能看到并真的能聊"这条
完整链路。

## 怎么跑起来

```bash
export UFT_TEST_WEB_DIR=test_web   # 相对 cwd；在仓库根目录下 go run 就对了
go run ./cmd/admin      # http://localhost:8081/ 是管理员页面
go run ./cmd/gateway    # http://localhost:8080/ 是用户页面
```

两个页面各自由对应的后端进程在根路径同源提供（页面内 JS 用相对路径
`fetch('/xxx')`），不需要跑单独的静态文件服务器，也不需要 CORS。

`UFT_TEST_WEB_DIR` 留空（默认）时两个进程的根路径都是普通 404——这套页面
默认不开启，不影响正常部署。

## 用法

1. 管理员页面：填 `UFT_ADMIN_TOKEN`（和 `cmd/admin` 启动时的配置一致）。
2. 第 1 步：填供应商信息（预填了 SiliconFlow 的 Base URL，Code/Name 随便改），
   API Key 填你自己的真实上游 Key，点"创建供应商 + 保存 Key"。
3. 第 2 步：点"获取模型列表"，会真的对上游发一次 `GET /models`。
4. 第 3 步：勾选想要的模型 → 点"①生成价格表"（会去 LiteLLM 社区价格数据集查一遍
   有没有现成的成本价，查得到的行自动填好，查不到的留 0 自己判断；售价永远是
   自己填，不会自动生成）→ 每行价格都能改 → 点"②导入"。
5. 第 4 步：点"创建测试账户..."，拿到一个 `RawKey`。
6. 用户页面：把 `RawKey` 粘贴进去，点"连接"——应该能看到第 3 步导入的模型；
   选一个，发一条消息，等真实上游的回复。

页面底部都有一个日志区，记录每一步的原始请求/响应，出问题直接看这里。
